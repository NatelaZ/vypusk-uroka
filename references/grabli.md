# Грабли конвейера выпуска — каждая куплена временем

## Видео и расшифровка
- **Натэла режет паузы после монтажа** (1.4, 1.11, 1.13, 2.2): итог короче рендера на 5–20 с, все
  тайминги монтажа сдвинуты. Конспект — только по перетранскрипции итога (`transcribe_final.py`).
- **Whisper на дорожке длиннее ~5 минут уходит в петлю** (повтор фразы ×80) и теряет пунктуацию —
  только чанками по паузам (`Монтаж/scripts/_transcribe_chunked.py`); `--prompt` не лечит.
- **Не пережимать уже сжатое:** рендер монтажа ~0,6 Мбит/с (1.0, 1.7, 1.12) — второй проход ест
  мелкий текст ради мегабайт; скрипт предупреждает «битрейт уже низкий» → заливать как есть.
  Файл Натэлы из редактора (3–4 Мбит/с, 250–700 МБ) — пережимать, h264 crf 21 (Kinescope-совместимо).
- Длительность после пережатия и на Kinescope обязана совпасть с файлом (±0,5 с).

## Kinescope
- **Дефолтный `kinescope_folder_id` в конфиге «Повторяемой задачи» ведёт в чужой проект** («Созвоны
  по четвергам») — урок 1.8 уехал туда. Проект курса передаётся явно из `courses.yaml`.
- **Обрыв сети при заливке оставляет мусорную запись** (`status: suspended, duration: 0`) — 1.14
  получил две. Ловится по `items_count` проекта до/после (+1 ровно); лишние удалять через API.
- Кириллица в HTTP-заголовке нельзя: сначала `X-Video-Title: upload`, потом PATCH названия JSON-ом.
- `short_id` из `play_link` — для embed и реестра; `uuid` — для API.
- **VPN не пропускает часть IP из DNS-пула Kinescope** (24.09.2026, урок 4.3 Томы): `api.kinescope.io`
  резолвится то в `46.102.104.4` (живой), то в `193.238.47.254` (ConnectTimeout, хотя ping идёт и порт 443
  отвечает — режется TLS). Сам `kinescope.io` при этом открывается, поэтому похоже на «API лежит». Лечение —
  запускать скрипты через обёртку, которая патчит `socket.getaddrinfo`: `api.kinescope.io` → `46.102.104.4`,
  `uploader.kinescope.io` → `46.102.104.5`. **Каждому хосту СВОЙ адрес**: прибить загрузчик к IP api —
  получить `413 Request Entity Too Large` (у того nginx лимит тела), и это выглядит как «файл слишком большой»,
  хотя дело в адресе. Образец обёртки — в задании `ВЫПУСК-4.3-ЗАДАНИЕ.md` урока 4.3 Томы.
- **Обёртка getaddrinfo не доходит до подпроцессов** (3.11, 24.09): `cover.py` зовёт `upload_posters.py` через
  `subprocess` — патч сокета в родителе там не действует, постер падает `ConnectTimeout uploader.kinescope.io`.
  Лечение: после рендера запустить `обложки-kinescope/scripts/upload_posters.py --only <short_id>` той же обёрткой.
  Снимок плеера: headless Chrome тоже резолвит `kinescope.io` в мёртвый 193.238.47.254; `--host-resolver-rules`
  на `kinescope.io` спасает страницу, но плеер виснет на CDN — проверять постер по API (`poster.status done, active`).
- **`--replace` рапортует «done» по СТАРЫМ ассетам** (3.2, 17.09): сразу после замены API отдаёт прежние 1080p/480p,
  новый транскод появляется через несколько минут. Готовность — по смене `file_size` ассетов и кадру из
  `download_link` на проблемном таймкоде, а не по статусу.

## Обложка
- `upload_posters.py`/`make_all.py` — **системным `python3`**, в venv «Повторяемой задачи» нет PIL.
- **Рендер обложки — с `--fit-height`** (24.09.2026, обложка 4.3 Томы): без него `background-size: cover`
  растягивает плашку 1536×1024 в 1,25× и срезает по ~100 px сверху и снизу — у одного из вариантов ушла
  макушка. С `--fit-height` вертикального среза нет.
- **Кнопка «плей» — круг d≈160 px по центру кадра** (x 879–1039, y 460–620 в 1920×1080): колонка
  текста до x=860, кегль подбирает `fit_fs`. Всё равно смотреть снимок живого плеера.
- **Одежда и поза — новая пара на каждой обложке** (правило Натэлы 26.07), гардероб только деловой
  casual, рукава подвёрнуты; классического/строгого пиджака любого цвета не бывает. Портрет —
  только через «Визуал» (эталон внешности), не своим промтом.
- **Кегль заголовка подбирается «по числу знаков», а не по кнопке «плей»** (4.6 Томы, 30.09.2026):
  `render_cover_tomat.py` даёт fs=100 всему, что короче 17 знаков, и «ШАПКА СООБЩЕСТВА» (16) вылезло
  правым краем на x=899 при пороге 860 — буквы подошли к кнопке вплотную. Проверять **до** заливки
  постера: правый край белого текста в полосе заголовка и счёт светлых пикселей в круге r≈80 вокруг
  центра кадра. Вылез — перерендерить с `--fs 88`, а не оставлять «вроде не наезжает».
- Тема — контраст к блоку конспекта, по реальным пикселям, не по CSS (у Вайбкодинга плеер в тёмном
  блоке → все обложки светлые).
- Текст обложки внутри курса называет тему урока, а не продаёт.
- **`cover.py` — только для Вайбкодинга** (импортирует `make_all` из его папки обложек; на курсе Томы
  падает `ModuleNotFoundError`). Обложка курса Томы (3.1, 3.2, 15.09): новая плашка —
  `Визуал/.venv/bin/python scripts/generate.py --brief "<текст брифа>" --count 2 --aspect 16:9
  --engines openai:gpt-image-2 --run tomat-NN-<odezhda> --out <обложки>/плашки/tomat-NN-<odezhda>`
  (бриф — текст, не файл; берётся из manifest.json соседней плашки с заменой строк «Одежда:» и
  «Поза:», занятые пары — грепом по manifest'ам); рендер — `обложки/render_cover_tomat.py --plate …
  --chip "УРОК N.N" --eyebrow "Нейрофото · Неделя N" --title … --sub … --out cover-N.N-sinii-v01.png`;
  постер — `POST uploader.kinescope.io/v2/poster` с `X-Video-ID: <uuid>` (JPEG байтами);
  снимок плеера — Chrome headless `--screenshot` на `kinescope.io/embed/<short_id>`.

- **`cover.py` не работает и для Нейроклуба** (МК 29.09): импортирует `make_all` из папки обложек Вайбкодинга,
  у клуба её нет. Обложка клуба = `render_cover.py` с двумя правками, живёт в
  `Нейроклуб/обложки-kinescope/scripts/render_cover_nk.py`: (1) портрет вписывается ПО ВЫСОТЕ
  (`right center/auto 100%`) — штатный `cover` у вертикального кадра 4:5 масштабирует по ширине и срезает голову,
  в кадре остаётся торс; (2) плашки-чипа нет — пустой `--chip` рисует синий огрызок. Стык фото с фоном гасится
  отдельным градиентом `.edge` (левые 480 px кадра), иначе серая стена фотостудии режет светлый фон полосой.
  Проверка кнопки «плей» — счётом тёмных пикселей в круге r≈82 вокруг центра (959, 540), а не на глаз.

- 🔴 **Проверять само видео на утечки, а не только свои кадры** (Б.3): в готовом уроке нашлись почта,

  --replace <short_id>` — id, ссылки и постер сохраняются. Границы масок сверять покадрово: конец
  интервала не должен заезжать на следующий слайд, а начало — обрываться раньше клипа.

  контактный лист до заливки; своё (пути `C:\Users\…`, суммы, ИП) Натэла показывает открыто.

## GetCourse
- **Страница fileindex грузится 8–12 с** из-за сторонних скриптов школы (`domfox.pro` и др.) —
  блокировать их через `route`, ждать поле `input[type=file]`, `wait_until="commit"`.
- **«Поле загрузки не появилось» ≠ «сессия протухла»** (3.4, 18.09): у куки `PHPSESSID5` в
  `_gc_state.json` истёк срок хранения, и браузер её выбрасывает, а сервер ту же сессию ещё принимает.
  Проверка до звонка Натэле: curl с куками на `https://<школа>.getcourse.ru/pl/fileindex/file/index` →
  200 и в теле `uploadifive` значит, что сессия жива. Лечение: продлить `expires` у `PHPSESSID5` в state
  (оригинал копией рядом) и заливать с `--resolve <домен-школы>=<IP <школа>.getcourse.ru>`, если `<домен-школы>`
  отдаёт пустой 404. Фаза адресов (`file/view`) при этом таймаутит — скрипт собирает адрес из хэша и сверяет байты.
- Сессия `output/getcourse/_gc_state.json` живёт несколько дней; протухла → нужен вход Натэлы,
  автологина в проекте нет (и не делаем).
- 🔴 **«Поле загрузки не появилось» чаще всего = страница думала дольше 30 с** (3.10, 23.09): скрипт ждёт
  поле 60×0,5 с и выходит, а `fileindex` под сторонними скриптами школы открывается то за 14 с, то за 40.
  Хуже того, `sys.exit` на этом месте **теряет хэши уже залитых файлов** — они пишутся только после всей
  фазы заливки, и 17 кадров из 30 пришлось восстанавливать регуляркой из лога. Проверка живости сессии —
  `requests` с куками **и заголовком User-Agent браузера**: без UA сервер отдаёт пустой 404 на любой
  адрес, и это не смерть сессии. Устойчивая дозаливка — `уроки-М3/3.10-…/_vypusk/upload_resume.py`:
  свежая вкладка на файл, три попытки по 90 с, хэш на диск после каждого файла; затем штатный
  `shots_upload.py --reuse-hashes` собирает адреса.
- Загрузчик `uploadifive` залипает после одного файла — свежая страница на каждый файл.
- GetCourse дедуплицирует файлы по содержимому (тот же файл → тот же URL); адрес картинки виден
  только на странице `file/view?hash=…`; `curl` без `-L` на fs.getcourse даёт 302 — это не битая ссылка.
- **Заливка — две фазы, и вторая тоже ходит на <домен-школы>** (2.3, 26.08): все 31 файл залились, а на
  первом же `file/view?hash=` — `ERR_TIMED_OUT`, хост школы (<IP фронта школы>) перестал отвечать даже по
  IP при живом fs.getcourse. Теперь `shots_upload.py` пишет хэши в `_src/gc_hashes.json` сразу после
  заливки, фазу адресов повторяет до трёх раз, а `--reuse-hashes` не заливает известное заново;
  `--resolve <домен-школы>=<ip>` обходит сломанный DNS. Пропал только хост — ждать, ничего не чинить.
- **`fs.getcourse.ru` отдаёт файл по хэшу с любым `sc/N`** (2.3, 26.08: хост школы упал второй раз посреди
  фазы адресов, 8 из 31 без URL). Номер `sc` в канонических адресах свой у каждого файла и ни на что не
  влияет: `…/sc/0/h/<hash>.jpg` скачался байт в байт. Скрипт теперь сам собирает такой адрес после трёх
  неудачных попыток и принимает его только после сверки md5 с локальным файлом; хэш GC — не md5 файла.
- **Фронт `<домен-школы>` лежит, а платформа жива** (2.9, 06.09): `Page.goto: ERR_TIMED_OUT` на
  fileindex, `curl` по DNS-адресу <IP фронта школы> молчит, но `<школа>.getcourse.ru` отвечает 302 на
  логин. Лечится `--resolve <домен-школы>=<IP платформы GetCourse>` — это IP платформы GetCourse (тот же, что у
  `<школа>.getcourse.ru`), сертификат для <домен-школы> там валиден, куки сессии подходят. Заливка
  прошла 26/26; на последних файлах фаза адресов всё равно таймаутила — адрес собрался из хэша (sc/0)
  и сверился байтами. IP платформы проверять `socket.gethostbyname_ex('<школа>.getcourse.ru')`, не
  вбивать из памяти.
- **Фоновую заливку не обрезать `| tail`**: хэши печатаются по одному на файл, и без полного лога
  их не восстановить (в 2.3 из 31 уцелели три). Полный вывод — в файл, `tail` — уже по файлу.
- Живой блок отстаёт от мастера / содержит лишнее → любые правки: `gc.py pull` → дифф → `push`.
- Тема школы перебивает `padding` ссылок-кнопок → `!important`; сущности и `&nbsp;` раскодируются.
- Блока конспекта в пустой заготовке нет — новый «Блок: HTML» добавляет Натэла в редакторе
  (Вставка → HTML), `gc.py push` пишет только в существующий блок.

## Конспект и база знаний
- `voice-lint` ругается на капслок имён файлов («ЕСЛИ-СЛОМАЛОСЬ») и служебных комментариев —
  ложные; «легко» в значении «легко промахнуться» тоже ловится — переформулировать.
- `kb_export.py` называет запись по первому по алфавиту mp4 → «base_slides»; поэтому только через
  `kb_export_lesson.py` (заголовок из `courses.yaml`, расшифровка итога, тайминги пересчитаны).
- **Лупа для скриншотов (клик → крупно) живёт в JS макета школы, а не в конспекте** (26.08.2026,
  по жалобам учеников на мелкие скриншоты): в КОНСПЕКТ.html ничего для неё не класть, локальный рендер
  `check_konspekt.py` её не показывает — это норма. Условие: картинка внутри `<figure>` — так и верстаем.
  Код, откат, проверка — `производство/оформление-getcourse/лупа-скриншотов/README.md`.
- **Белым по белому: светлый блок внутри тёмной секции.** На 4.2 блок «Если что-то пошло не так»
  (`.nfXX-help`, фон #fff) лёг внутрь финальной синей секции (`.nfXX-next`, `color:#fff`) — и весь текст
  стал невидимым. `check_konspekt.py` этого не ловит (теги парны, картинки на месте), поймалось только
  глазами на `render_desktop_end.png`. Переносите светлую карточку в тёмную секцию — сразу дописывайте
  `.nfXX-next .nfXX-help{color:var(--tm-ink);}` для текста, `b` и `a`. **Рендеры top/mid/end смотреть
  глазами каждый раз, а не только читать «проверки: чисто».**
- **`kb_export_lesson.py` падает на двоеточии в `--title`** (29.09.2026, МК про галлюцинации):
  `render_markdown` пишет заголовок во фронтматтер без кавычек, YAML видит «Мастер-класс «…»: …»
  как вложенный ключ → `kb add` отваливается с `ScannerError: mapping values are not allowed here`,
  а `kb_entry.md` при этом уже записан. Лечение: открыть `final/kb_entry.md`, взять `title:` в
  одинарные кавычки и добавить руками — `kb add <файл> --on-duplicate update` + `kb reindex`.
  Там же правится `id`: шаблон `kb_id` для созвонов даёт дубль даты
  (`urok-2026-09-29-neyroklub-2026-09-29`) — для мастер-класса имя даём по теме.
- **Тема вида `21:9` в `--topics` роняет `kb add`** (4.6 Томы, 30.09.2026): YAML читает `21:9` как
  шестидесятеричное число и кладёт во фронтматтер `1269`, а `kb` падает на `', '.join(entry.topics)` —
  `TypeError: expected str instance, int found`. Запись при этом **уже записана**, с числом вместо темы,
  поэтому «упало» ≠ «не выгрузилось»: проверять `kb get <id>` и перезаписывать. Форматы и любые
  «цифра:цифра» в темах писать словами — «формат 21 к 9».
- В базу знаний — только после «принято» Натэлы.

## Уборка: Finder сносит мимо Корзины, а шелл Корзину не видит (4.6, 03.10.2026)

`osascript -e 'tell application "Finder" to move POSIX file "…" to trash'` пачкой по крупным
файлам **отваливается по таймауту AppleEvent** (`execution error … (-1712)`) на середине списка:
первые пункты уехали, остальные — нет, а код выхода при этом 0. Хуже другое: двух файлов
(`Тома 4.6.mp4` 377 МБ и `Нейрофото 4-6.mp4` 55 МБ) после этого **не оказалось ни в Корзине,
ни вообще на диске** — из Загрузок исчезли, в Корзине Finder видит 0 таких элементов, поиск по
диапазону размеров по всей домашней папке пустой. То есть «move to trash» на больших файлах
может сработать как безвозвратное удаление, и обещанных скиллом «суток на откат» не будет.

Как убирать:
1. **Не Finder, а `mv` в Корзину:** `D="$HOME/.Trash/<урок>-ubrano-<дата>"; mkdir -p "$D"; mv … "$D/"`.
   Один том (`df` показывает `/dev/disk3s5` и для `~/.Trash`, и для `Монтаж`, и для `~/Movies`) —
   переезд мгновенный, файл реально лежит в Корзине, откат вручную.
2. **Считать уборку сделанной только после проверки, что файл в Корзине.** «Исчез из исходной
   папки» ≠ «в Корзине». Проверять `du -sh "$D"/*`, а по чужим переносам — через Finder:
   `osascript` с `count of items of trash` и перебором `name of (item k of trash)`.
   Из шелла `ls ~/.Trash` даёт `Operation not permitted` (TCC) — списка оттуда не получить.
3. **Папки в `~/.Trash` переезжают медленно, если они в iCloud Drive:** 481 МБ автосъёмки
   (`_syntx-auto/video/Sh-<блок>-*`) тянулись минутами, потому что файлы dataless. Гнать фоном
   (`run_in_background`), не в 120-секундном таймауте.
4. **Глоб во входе не использовать** даже в `mv` (память `feedback-ffmpeg-bez-globa-vo-vhode`):
   папки автосъёмки перечислять явным списком — `*4.6*` рядом цепляет `4.61`, `4.612` и прочее.
